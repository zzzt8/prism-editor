# Prism Editor 产品定位与产品形态 PRD v0.2

> 本文档是 `Prism Editor PRD v0.1` 的 **定位补充与产品形态澄清**。
> 用于明确：
> - 用户视角与开发者视角的边界
> - 实时预览模式 vs 后端批量处理模式
> - 接入 mall 项目的形态
> - 独立软件的长期形态

---

## 1. 文档目的

v0.1 PRD 回答了「Prism Editor 是什么」和「第一阶段要做什么」。
但在实际推进中，我们发现**「用户实际看到什么」**与**「开发者如何编排工作流」**之间存在认知鸿沟，导致：

- 实时合成性能问题被误归类为"卡顿 bug"
- 工作流节点 UI 是否暴露给用户没有明确
- 实时合成与后端合成的边界模糊

本文档**不替代** v0.1，而是补充一个关键问题：

> **用户最终看到的，应该是一个画布，而不是一个工作流编辑器。**

---

## 2. 双视角核心概念

Prism Editor 同时存在两种视角，必须严格区分：

| 视角 | 角色 | 看到的内容 | 使用的工具 |
|------|------|-----------|----------|
| **用户视角** | mall 项目 chat 页面用户 | **一个画布**，可拖拽置入图片 | 嵌入 mall 项目的画布组件 |
| **开发者视角** | 内部设计师 / 运营 | 完整的工作流节点编辑器 | dev-tool（仅内部） |

**关键约束**：

- **用户**只看到**一个画布**，**绝对看不到**任何节点 UI
- **用户**可以**拖拽图片**调整位置，**效果实时呈现**（像 PS 一样）
- **dev-tool** 仅供内部使用，**用户不会接触到**
- 工作流（节点组合）只是**实现手段**，不是用户产品

---

## 3. 两种合成模式

| 模式 | 触发场景 | 分辨率 | 实时性 | 用途 |
|------|---------|--------|--------|------|
| **前端实时预览** | 用户在画布上拖拽、调整 | 缩略图（**384px**） | 实时（拖拽中零延迟，停止后合成） | 给用户预览效果 |
| **后端批量处理** | mall 项目确认下单后 | 全分辨率（原图） | 异步，不要求实时 | 生成最终图包 |

**两种模式使用同一套工作流定义**：
- 工作流是图像合成的"配方"
- 前端用这个配方做缩略图预览
- 后端用这个配方做全分辨率生产

---

## 4. 用户视角核心交互

### 4.1 用户看到的界面

```
┌─────────────────────────────────────────────────┐
│                                                  │
│              【画布 - 用户的全部世界】             │
│                                                  │
│         ┌──────────┐                             │
│         │  背景图   │  ← 可拖拽                  │
│         └──────────┘                             │
│              ┌──────────┐                        │
│              │  装饰图   │  ← 可拖拽              │
│              └──────────┘                        │
│                                                  │
│  用户看到的就是这个画布                            │
│  没有任何节点、连线、参数面板                      │
│                                                  │
└─────────────────────────────────────────────────┘
```

### 4.2 用户的操作

| 操作 | 说明 |
|------|------|
| 拖拽图层 | 在画布上拖动图片到目标位置 |
| 查看效果 | 拖拽时实时看到合成效果（CSS transform 实时跟随） |
| 确认下单 | 点击确认按钮，触发后端合成 |

### 4.3 用户**看不到**的东西

- 节点（Node）
- 边（Edge）
- 节点参数面板
- 工作流编辑器
- 任何 "composite"、"transform" 字样

## 5. 开发者视角（dev-tool）

### 5.1 dev-tool 的定位

| 维度 | 说明 |
|------|------|
| 角色 | 内部设计师 / 运营 配置工作流的工具 |
| 用户 | **仅内部使用** |
| 形态 | 类 ComfyUI 节点编辑器 |
| 产物 | 发布到后端的「工作流定义」 |

### 5.2 dev-tool 的工作流

```
设计师在 dev-tool 中编排工作流
       ↓
例如：[LoadImage:bg] → [Transform:居中] → [Composite] → [Export]
       ↓
保存并发布到后端（关联到 mall 的某个 SKU）
       ↓
用户在 mall chat 页面看到的，就是这个工作流的"用户视图"
       ↓
用户在画布上拖拽图片调整位置
       ↓
点击确认下单
       ↓
后端用同样的工作流做全分辨率合成
       ↓
生成图包返回给 mall
```

## 6. 前端实时预览架构

### 6.1 关键技术决策

| 决策点 | 结论 | 理由 |
|--------|------|------|
| 预览分辨率 | **384px** | 1. 手机上正好占满屏幕宽度；2. 体积小，合成快；3. 细节足够看清 |
| 拖拽对象 | **图层**（图片在画布上的位置） | 符合 PS 的用户心智模型 |
| 拖拽中行为 | **CSS transform 实时跟随** | 不触发任何合成计算，0 延迟 |
| 拖拽结束行为 | 停止 100ms 后触发缩略图合成 | 拖完再合成，节流 |
| 合成计算 | **Worker 异步** | 不阻塞主线程 |
| 缩略图生成 | 加载图片时生成 384px 缩略图 | 不在拖拽时缩放 |

### 6.2 数据流

```
用户拖拽图层
    ↓
拖拽中：CSS transform 实时跟随（不合成，0 延迟）
    ↓
拖拽结束（pointerup）
    ↓
触发缩略图合成（Worker，384px）
    ↓
画布更新显示合成结果
    ↓
用户继续拖拽 / 点击确认下单
```

## 7. 后端批量处理架构

### 7.1 触发时机

**由 mall 项目决定**（订单确认后等），本工具只提供 API 能力。

### 7.2 处理流程

```
mall 触发后端合成 API
    ↓
后端读取工作流 + 用户调整后的图层位置
    ↓
全分辨率合成（sharp）
    ↓
生成图包
    ↓
返回给 mall
```

### 7.3 后端能力范围

- ✅ 提供合成 API
- ✅ 接收工作流定义 + 图层位置参数
- ✅ 全分辨率合成（sharp）
- ✅ 生成图包
- ❌ 不负责 mall 业务逻辑（订单、支付等）

## 8. 节点系统

Prism Editor 第一阶段使用 5 种基础节点：

| 节点 | 功能 |
|------|------|
| LoadImage | 加载图片 |
| Transform | 位置 / 缩放 / 旋转 |
| Mask | 蒙版（透明度 / 亮度） |
| Composite | 合成（混合模式） |
| Export | 导出 |

> **注意**：这是**实现手段**，不是用户可见的产品功能。

## 9. 接入 mall 项目

### 9.1 形态

- Prism Editor 以 **嵌入组件** 形式接入 mall chat 页面
- mall 提供：素材（用户上传的图片、生成的 AI 图等）
- Prism Editor 提供：画布 + 实时合成 + 确认下单
- 后端通过 API 通信

### 9.2 边界

| 属于 Prism Editor | 属于 mall |
|-------------------|----------|
| 画布 UI | chat 页面 |
| 实时合成逻辑 | 素材管理 |
| 工作流编排 | 订单流程 |
| 后端合成 API | 支付 / 用户账户 |
| 图包生成 | 图包存储 / 分发 |

## 10. 独立软件的长期形态

完成 mall 接入后，Prism Editor 计划独立为一个软件：

| 阶段 | 目标 |
|------|------|
| **当前** | mall chat 页面的图像合成工具 |
| **近期** | 支持更多品类、更多节点类型的 mall 工具 |
| **中期** | 独立 SaaS，提供画布 + 工作流编排服务 |
| **远期** | 类 n8n + ComfyUI 的工作流平台 + 节点生态 |

**架构要求**：
- dev-tool / 用户画布 / 后端服务 **职责清晰**
- 节点系统 **可扩展**（支持新增节点类型）
- 工作流 **可保存、发布、版本管理**
- 未来可拆分为独立产品

## 11. 设计目标总结

### 11.1 前端体验目标（用户视角）

- ✅ 拖拽图片 **零延迟**，像 PS 一样顺滑
- ✅ 合成效果 **实时呈现**
- ✅ 画布 **只显示合成结果**，不显示任何节点 UI
- ✅ 不暴露任何工作流概念给用户

### 11.2 后端能力目标（mall 接入）

- ✅ API 接口清晰，可由 mall 触发全分辨率合成
- ✅ 支持用户调整后的图层位置作为输入
- ✅ 批量生成图包
- ✅ 后端合成逻辑可由 mall 自定义

### 11.3 架构目标（独立软件未来）

- ✅ dev-tool 仅内部使用
- ✅ 用户画布组件可独立嵌入任意宿主
- ✅ 节点系统可扩展
- ✅ 工作流可保存、发布、版本管理
- ✅ 前端实时 / 后端批量 两种模式共用同一份工作流定义

---

## 12. 非目标（Out of Scope）

本文档**明确不包含**以下范围：

- ❌ **不做新的节点类型**（用现有 5 种：LoadImage / Transform / Mask / Composite / Export）
- ❌ **不做图层旋转/缩放的画布拖拽**（位置可拖拽，旋转/缩放通过参数面板或后续 PRD 规划）
- ❌ **不做图层锁定 / 层级管理 UI**（只支持位置调整）
- ❌ **不实现图层选择 UI**（用户只看到最终合成图，不选择图层）
- ❌ **不做图层添加 UI**（用户不直接添加图层，由 mall 传入图片）
- ❌ **不做画布撤销 / 重做**（v1 不做，后续 PRD 规划）
- ❌ **后端合成具体业务逻辑**（由 mall 自定义，我们只提供 API 和节点执行能力）
- ❌ **dev-tool 不对外暴露**（仅内部使用）
- ❌ **不暴露节点 UI 给最终用户**（用户在画布里看不到任何节点）

## 13. 已识别的技术债务

| 问题 | 说明 | 后续处理 |
|------|------|---------|
| 实时合成卡顿 | 当前每次操作都触发完整 workflow 执行 | 后续 change：CSS transform 优化 + 缩略图 |
| 拖拽与合成耦合 | 拖拽过程中没有 CSS transform 优化 | 后续 change：拆分拖拽与合成 |
| user-app 定位不清 | v0.1 中 user-app 是模拟用户，未来实际不直接使用 | 后续 change：明确 user-app 仅作 dev/测试用途 |
